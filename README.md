# 💌 우리 퀴즈 배틀

연인과 **실시간으로** 서로를 얼마나 아는지 겨루는 웹 퀴즈 게임입니다. 서버 없이 GitHub Pages(화면) + Firebase(실시간 동기화)로 동작해요.

## 게임 방식

1. 한 명이 방을 만들고 6자리 코드(또는 초대 링크)를 상대에게 보내요.
2. 로비에서 둘만 아는 질문을 추가할 수 있어요. 선택지를 적으면 객관식, 비우면 직접 입력 질문이 돼요. 기본 질문과 섞여 총 10문제가 나와요.
3. 각 문제마다 **내 진짜 답**과 **상대가 쓸 것 같은 답**을 함께 입력해요.
4. 둘 다 제출하면 **동시에 공개**되고, 서로의 추측이 맞았는지 판정해요.
5. 10문제가 끝나면 점수와 문제별 기록이 나와요.

## 정답 판정 방식 (`judge.js`)

질문은 두 종류예요.

- **선택형(객관식)**: 선택지가 같아야 정답이에요. 자동으로 정확하게 판정돼요.
- **자유 입력**: 아래 순서로 먼저 자동 비교하고, 자동으로 정답이 아닌 답은 **진짜 답을 쓴 사람이 직접 판정**해요.

자유 입력의 자동 비교 순서는 이래요.

1. **정규화**: 공백·특수문자 제거, 영문 소문자 통일, 한글 유니코드 통일, 흔한 꼬리말("~이야", "~요") 제거
2. **오타 허용**: 한글을 자모(ㄱ, ㅗ, ㅂ…)로 쪼갠 뒤 편집 거리 계산
   - 한 글자: 오타 허용 없음 (밥 ≠ 빵)
   - 두~세 글자: 자모 1개 차이까지 (곱창 = 곱참)
   - 긴 단어: 자모 2개 차이까지
   - 숫자가 들어간 답은 정확히 일치해야 정답 (1988 ≠ 1989)
3. **포함 관계**: 한쪽이 다른 쪽을 포함하면(곱창 / 소곱창) "비슷해 보여요!"라고 안내하며 진짜 답 주인에게 판정을 맡겨요.
4. **그 외**: 자동으로 맞지 않으면 진짜 답 주인이 "정답으로 인정 / 오답" 중에서 골라요. 판정이 끝나야 다음 문제로 넘어가고, 판정은 나중에 "판정 바꾸기"로 바꿀 수 있어요. (동의어 처리용)

허용 기준은 `judge.js`의 `allowedDistance`에서 조절할 수 있어요. 테스트는 `npm test` (또는 `node judge.test.mjs`).

## 설정 방법

### 1. Firebase 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들어요.
2. **빌드 → Authentication → 시작하기 → 로그인 방법 → 익명** 을 사용 설정해요.
3. **Authentication → 설정 → 승인된 도메인** 에 배포할 도메인을 추가해요. (예: `내아이디.github.io`) `localhost`는 기본으로 들어 있어요.
4. **빌드 → Realtime Database → 데이터베이스 만들기** (위치는 가까운 곳, 모드는 잠금 모드).
5. Realtime Database의 **규칙** 탭에 `database.rules.json` 내용을 붙여넣고 게시해요.
6. **프로젝트 설정 → 내 앱 → 웹 앱(</>) 추가** 후 보이는 설정값을 `firebase-config.js`에 붙여넣어요.
   Realtime Database를 만든 **뒤에** 복사해야 `databaseURL`이 들어 있어요.

### 2. 내 컴퓨터에서 테스트

ES 모듈을 쓰기 때문에 파일을 더블클릭하지 말고 로컬 서버로 열어야 해요.

```bash
npm start        # 또는: python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 열고, 탭 두 개(하나는 시크릿 창)로 방 만들기 / 참가를 해보면 혼자서도 테스트할 수 있어요.

### 3. GitHub Pages로 배포

1. 이 폴더를 GitHub 저장소에 올려요.
2. 저장소 **Settings → Pages → Build and deployment → Deploy from a branch** → `main` / `(root)` 선택.
3. 몇 분 뒤 `https://내아이디.github.io/저장소이름/` 에서 열려요.
4. 1단계 3번처럼 `내아이디.github.io`를 Firebase 승인된 도메인에 꼭 추가해야 해요.

## 알아둘 점

- **보안 규칙**: 방 코드를 아는 사람만 방을 읽을 수 있고, 방에 들어간 두 사람만 쓸 수 있어요. 방은 최대 2명까지만 참가 가능해요.
- **답 숨김은 화면에서만**: 상대의 답은 둘 다 제출하기 전까지 화면에 안 보이지만, 개발자 도구로 데이터를 직접 열어보면 볼 수 있어요. 커플끼리 하는 게임이라 허용했어요.
- **방 정리**: 방 데이터는 자동으로 삭제되지 않아요. 가끔 Firebase 콘솔에서 `rooms`를 비워주세요.
- `firebase-config.js`의 값은 공개되어도 괜찮지만, 무료 구간(Spark)을 넘지 않는지 가끔 확인하세요.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html`, `style.css` | 화면 |
| `app.js` | 방 만들기/참가, 실시간 동기화, 게임 진행 |
| `judge.js` | 정규화·오타 허용·포함 관계 판정 |
| `judge.test.mjs` | 판정 로직 테스트 |
| `questions.js` | 기본 질문 (선택형 13개 + 자유 입력 23개) |
| `firebase-config.js` | Firebase 설정값 (직접 채우기) |
| `database.rules.json` | Realtime Database 보안 규칙 |
